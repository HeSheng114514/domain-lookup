快速上手

在顶部输入框里填域名,按 Enter 或点「查询」即可。输入很宽松,下面这些写法都能识别:

  • example.com —— 标准写法
  • https://example.com/path?a=1 —— 会自动剥掉协议、路径、参数
  • example.com:8080 / user@example.com —— 端口和用户名会被忽略
  • 中国互联网络信息中心.中国 —— 中文域名会自动转成 punycode 再查询

WHOIS 查询

查询不是简单地请求一个网址,而是完整走一遍 WHOIS 协议:

  • 先在内置的 206 个顶级域映射表里找注册局服务器;找不到的会自动去 whois.iana.org 查 refer 字段动态发现,所以冷门后缀也能查。
  • 通过 TCP 43 端口直连注册局。
  • 很多注册局(比如 Verisign 的 .com)只返回"薄"数据,应用会自动读响应里的 Registrar WHOIS Server 字段,再跳到注册商服务器查一次, 把注册人、滥用举报邮箱等信息也拿回来。

结果会被解析成结构化字段:注册商、注册/到期/更新日期、域名年龄、剩余天数、 EPP 状态码(带中文解释)、域名服务器、DNSSEC 状态。

「概览」页顶部的时间轴会直观显示域名生命周期 —— 绿色是正常,橙色表示 45 天内到期, 红色表示已经过期。

EPP 状态码速查

状态码含义
clientTransferProhibited客户端禁止转移 —— 域名被锁定,防止被恶意转出(正常保护措施)
clientHold客户端暂停解析 —— 通常因为邮箱未验证或欠费
serverHold注册局暂停解析 —— 更严重的暂停
redemptionPeriod赎回期 —— 已过期,原持有人可高价赎回
pendingDelete待删除 —— 即将释放,很快可以重新注册

DNS 记录

支持 A、AAAA、CNAME、MX、NS、 TXT、SOA、CAA、SRV、PTR 全部常见类型,结果按类型分组显示。

可用性检测

判断能不能注册,单看任何一个数据源都不靠谱,所以这里用三源交叉验证:

数据源判为「已注册」判为「可注册」
WHOIS存在注册记录返回 no match
DNS存在 NS 或 SOA 委派NS 和 SOA 都返回 NXDOMAIN
RDAP返回域名对象返回 404
为什么不用 A 记录判断? 因为 NXDOMAIN 劫持很常见 —— 部分运营商和企业 DNS 会把不存在的域名解析到广告页或保留地址段 (198.18.0.0/15 之类),凭空造出一条 A 记录。而已注册的域名一定有 NS 委派。 应用会检测这种异常并在结果里标注。

三个数据源会各自投票,结论不一致时按「已注册」处理并降低置信度, 同时在「依据」里列出每一票的具体理由。

批量查询

展开页面下方的「批量查询 / 可用性检测」,每行填一个域名(或用空格、逗号分隔), 最多 200 个。结果会实时流式逐个返回,不用等全部查完。 并发数可以调,但调太高容易触发注册局限流。

导出与分享

  • 结果上方有一排按钮:复制摘要、导出 JSON / CSV / TXT。
  • 查询完成后窗口地址会带上域名参数,可以直接复制给人。
  • 菜单「文件 → 打印 / 另存为 PDF」可以把当前结果存成 PDF (打印时会自动隐藏搜索框和按钮,只留结果)。

已知限制

  • 不是所有后缀都支持 WHOIS —— 少数新 gTLD 只有 RDAP,应用会自动降级。
  • 注册人信息大多已脱敏 —— 受 GDPR 和 ICANN 临时政策影响,绝大多数域名的 注册人姓名、邮箱、地址都不再公开。这是行业现状,不是查询失败。
  • WHOIS 有限流 —— 注册局对同一 IP 有频率限制。应用已做节流和退避重试, 但短时间大量查询仍可能触发,此时结果会标注「注册局限流,结果可能不完整」。
  • 可用性仅供参考 —— 交叉验证能大幅提高准确率,但最终能否注册还取决于 注册商的实时状态(溢价域名、保留域名等)。批量结果请以注册商为准。
  • 日期时区 —— 注册局返回不带时区的时间一律按 UTC 解释(这是惯例)。 极少数注册局若用本地时间,可能偏差几小时。

网络说明

应用启动时会在本机 127.0.0.1 上开一个随机端口的 HTTP 服务, 界面就是从这个本地服务加载的。这个服务只监听回环地址, 局域网和公网上都访问不到,不会暴露任何信息。 所有查询请求都由本机直接发往注册局的 WHOIS(43 端口)和 RDAP(443 端口), 不经过任何第三方网站或接口。
